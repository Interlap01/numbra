# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Numbra is an iOS-first SwiftUI paint-by-numbers app. The user picks a photo or a
built-in sample, chooses a difficulty, and the app generates a numbered, paintable
canvas they color in by tapping/dragging regions. Features: progress tracking, hints,
undo, magic-fill, sound, timelapse replay, XP/levels/streaks/achievements, a daily
challenge, themed packs, and a Plus paywall.

The Swift code is a **faithful port of the HTML/React design prototype** in
`design_handoff_numbra/`. That directory's `README.md` is the authoritative spec for
look, behavior, tokens, and the engine algorithm — read it before changing engine,
canvas, or UI logic. Source files carry comments pointing back to the `.jsx` file they
were ported from (e.g. `// app.jsx App`, `pbn-engine.jsx`). The `.jsx`/`.html` files are
reference only — **do not ship or edit them**; change the Swift.

## Build & run

The Xcode project is **generated by XcodeGen** from `project.yml` — `Numbra.xcodeproj`
is a build artifact. After adding/removing/renaming files under `Sources/`, regenerate:

```sh
xcodegen generate          # rebuild Numbra.xcodeproj from project.yml
```

Build / run from the command line:

```sh
xcodebuild -project Numbra.xcodeproj -scheme Numbra \
  -destination 'platform=iOS Simulator,name=iPhone 16 Pro' build
```

Deployment target is **iOS 26.0** (see `project.yml`); bundle id `run.mobai.numbra`.
There is no test target, no linter config, and no package manager — pure first-party
frameworks (SwiftUI, UIKit, CoreGraphics, QuartzCore, AVFoundation).

To edit build settings, deployment target, or bundle id, change `project.yml` and
regenerate — edits to the `.xcodeproj` are overwritten.

## Architecture

The flow is **engine → data → imperative canvas → SwiftUI shell**.

### State machine (`Sources/ContentView.swift`, `Sources/Model/AppModel.swift`)
`AppModel` is a single `@MainActor @Observable` class holding all app state and the
navigation `screen` enum (`gallery, upload, difficulty, processing, paint, complete`).
`ContentView` is the root router: it switches on `model.screen` for the active screen
and layers global overlays/sheets (toast, timelapse, share, achievements, pack, paywall)
in a `ZStack` with explicit `zIndex`. There is **no NavigationStack** — navigation is
state mutation on `AppModel`. Overlays/sheets are driven by optional properties
(`overlay`, `packSheet`, `paywall`, etc.) going non-nil.

Persistence is `UserDefaults` keys (`numbra_onboarded`, `numbra_tut`) and the
`Progression` store; projects/sessions live in memory on `AppModel.projects` (not
persisted across launches). Samples are built procedurally on `bootstrap()` via
`PBNSamples.make` on a detached task.

### The PBN engine (`Sources/Engine/`)
`PBNEngine.generate(_:options:)` is **pure, platform-agnostic** image→data logic, run on
a detached background task in `AppModel.runEngine`. Pipeline (keep faithful to the spec):
downscale to `detail` px long-side → median-cut quantization to `colors` → nearest-color
index map → 3×3 majority smoothing → connected-component labeling (4-connectivity,
iterative stack) → two passes of small-region merging into dominant neighbor → palette
sorted light→dark and renumbered → per-region color/centroid/pixel-list/boundary
segments. Output is `PBNData` (`PBNData.swift`), a reference type whose `labels` array
gives **O(1) hit testing** (`labels[iy*w+ix]` → region id). Difficulty presets live in
`Difficulty.all` (Easy/Medium/Hard = colors 10/16/24, detail 66/96/132).

### The interactive canvas (`Sources/Canvas/`)
Deliberately **outside the observable store** for performance — re-rendering per fill
would not perform. Three layers:
- `PaintCanvasEngine` — pure model: fill/highlight RGBA buffers, boundary `CGPath`,
  image→screen `Transform`, fill/undo order stack, mistake count, and transient
  hint/magic/ring effects. Imperative API (`hint`, `magicFill`, `undo`, `zoomBy`,
  `fitView`, `tryFillAt`, `paintStroke`, `getState`) and callbacks
  (`onFillChange`, `onComplete`, `onWrong`, `onFill`, `onMagic`, `onNeedsDraw`).
  `advance(now:)` steps all time-based animations each frame.
- `PaintCanvasUIView` (in `PaintCanvasView.swift`) — layer-backed `UIView` doing Core
  Graphics drawing + raw multitouch gesture handling. **Preserve the redraw resilience:**
  a `CADisplayLink` plus a **~45ms `Timer` fallback** that guarantees a paint even when
  the link is throttled — this mirrors the prototype's rAF+timeout fallback.
- `PaintCanvas` — `UIViewRepresentable` bridging the UIView into SwiftUI.

Mistake-proof rule: a tap/stroke on a region whose color ≠ selected color **never
fills** — it records a mistake and triggers wrong-feedback. Fill order drives both undo
and the timelapse replay. `getState()` snapshots `{filled, order, mistakes, done, total}`
for session save/restore (`AppModel.saveSession`/`finishPaint`).

### UI layer
- `Sources/UI/Theme.swift` — design tokens (colors via `Color(hex:)`, type via
  `Theme.display` serif / `Theme.ui` sans). Use these, not raw colors.
- `Sources/UI/Components.swift`, `Icon.swift` — shared atoms (buttons, rings, icons).
- `Sources/Screens/` — one file per screen plus `Overlays.swift`, `Sheets.swift`,
  `Shared.swift`, `StudioExtras.swift`. Each `*View` takes `model: AppModel`.
- `Sources/FX/` — `SoundFX` (AVFoundation pluck/chord/ambience), `Confetti`.
- `Sources/Model/Progression.swift` — XP/levels/streaks/achievements, persisted under
  `numbra_progress_v1`. `levelFor(xp)`, `recordCompletion(...)`, `dailyIndex(n)`.

### Paywall gates
Custom-photo upload, Hard difficulty, premium packs, and HD share export are all
Plus-gated. They check `model.isPlus` and set `model.paywall` when locked; on purchase a
pending `Difficulty` config in `paywall` resumes canvas creation.

## Conventions

- Keep the engine and `PaintCanvasEngine` **pure and non-observable**; drive the canvas
  imperatively. Never move canvas per-fill state into `@Observable`.
- When porting/altering behavior, cross-check `design_handoff_numbra/README.md` and the
  referenced `.jsx` file — the comments name the source.
- Pixel buffers are RGBA `[UInt8]` (`premultipliedLast`), accessed via
  `withUnsafeMutableBufferPointer` in hot loops — match that pattern for new buffer ops.
